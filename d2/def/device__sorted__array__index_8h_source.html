2  * @file device_sorted_array_index.h
3  * @brief GPU-based Sorted Array Index (Read-Only B-Tree / Flat Index) for GPU kernels
4  *
5  * @details This index stores the indexed columns in a contiguous, sorted layout on GPU device
6  * memory. Unlike the CPU version, this uses device pointers and POD-style Handle structures that
7  * can be safely copied to and used within GPU kernels.
8  *
9  * @section gpu_design GPU Design Considerations
10  * - **POD Handle**: NodeHandle is a Plain Old Data structure containing only device pointers and
11  * indices, making it safe to copy to GPU and use in kernels
12  * - **Device Memory**: All data is stored in DeviceArray containers using RMM (RAPIDS Memory
13  * Manager) allocators
14  * - **Kernel-Compatible**: Handle can be passed to GPU kernels via kernel launch parameters
15  * - **Coalesced Access**: Data layout optimized for GPU memory coalescing patterns
16  *
17  * @section tradeoffs Trade-offs vs CPU SortedArrayIndex
18  * - **Pros:**
19  * - GPU-accelerated search and traversal operations
20  * - Parallel processing of large datasets
21  * - Memory coalescing optimizations for GPU
22  * - **Cons:**
23  * - Requires GPU memory transfers for host-device data movement
24  * - Handle must be POD (no host pointers or complex types)
25  * - Kernel launch overhead for small operations
26  *
27  * @tparam SR The semiring type
28  * @tparam AttrTuple The attribute tuple type
29  * @tparam ValueType The type for encoded values (default: uint32_t for memory efficiency)
30  * @tparam RowIdType The type for row IDs (default: uint32_t)
31  */

233  /**
234  * @brief POD-style Handle for GPU kernel usage (fatty pointer, need slim down in future)
235  *
236  * @details NodeHandle is a Plain Old Data structure containing only:
237  * - Device pointers (safe to copy to GPU)
238  * - Indices and offsets (POD types)
239  * - No host pointers or complex types
240  *
241  * This design allows the Handle to be:
242  * - Copied to GPU memory via kernel launch parameters
243  * - Used directly in GPU kernels
244  * - Stored in device memory for persistent queries
245  *
246  * @warning Handle Lifetime: Handles contain raw pointers to device memory that may be
247  * invalidated when the index is modified. The following operations invalidate
248  * all existing handles:
249  * - merge(): Rebuilds may reallocate memory
250  * - build_from_encoded_device(): Rebuilds the entire index
251  * - clear(): Deallocates all memory
252  *
253  * @warning Always call root() AFTER operations that modify the index to get a fresh handle.
254  * Do NOT reuse handles across merge/build/clear operations, as this will result
255  * in dangling pointers and undefined behavior.
256  *
257  * @note All device pointers must remain valid for the lifetime of the Handle usage.
258  * Since C++ doesn't have borrow checking, it's the caller's responsibility to
259  * ensure handles are not used after invalidation.
260  */
