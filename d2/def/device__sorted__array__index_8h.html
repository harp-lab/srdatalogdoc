Detailed Description

GPU-based Sorted Array Index (Read-Only B-Tree / Flat Index) for GPU kernels.

This index stores the indexed columns in a contiguous, sorted layout on GPU device memory. Unlike the CPU version, this uses device pointers and POD-style Handle structures that can be safely copied to and used within GPU kernels.

GPU Design Considerations

  • POD Handle: NodeHandle is a Plain Old Data structure containing only device pointers and indices, making it safe to copy to GPU and use in kernels
  • Device Memory: All data is stored in DeviceArray containers using Umpire allocators
  • Kernel-Compatible: Handle can be passed to GPU kernels via kernel launch parameters
  • Coalesced Access: Data layout optimized for GPU memory coalescing patterns

Trade-offs vs HashTrieIndex

  • Pros:
  • GPU-accelerated search and traversal operations
  • Parallel processing of large datasets
  • Memory coalescing optimizations for GPU
  • Cons:
  • Requires GPU memory transfers for host-device data movement
  • Handle must be POD (no host pointers or complex types)
  • Kernel launch overhead for small operations
