109 // Encoding/Decoding System: Why Codec?
110 // ============================================================
111 /**
112  * @section codec_motivation Motivation for Encoding
113  *
114  * The codec system converts all attribute values to a uniform `size_t`
115  * representation for use in HashTrieIndex structures. This design provides
116  * several critical performance and architectural benefits:
117  *
118  * @subsection codec_uniform_size Uniform Value Size
119  *
120  * - **Even-length values**: All encoded values are `size_t` (typically 8
121  * bytes), ensuring uniform key sizes in index structures
122  * - **Simplified comparisons**: Index operations compare fixed-size values,
123  * enabling efficient SIMD operations and better branch prediction
124  * - **Memory alignment**: Uniform sizes improve cache line utilization and
125  * reduce memory fragmentation
126  *
127  * @subsection codec_join_performance Join Performance
128  *
129  * - **Fast key comparisons**: Fixed-size encoded keys enable efficient hash
130  * table lookups and trie traversals during joins
131  * - **Reduced comparison overhead**: No need for type-specific comparison logic
132  * in hot join paths (e.g., string comparison vs. integer comparison)
133  * - **Better hash distribution**: Uniform encoding improves hash function
134  * effectiveness for join algorithms
135  *
136  * @subsection codec_communication Distributed Communication
137  *
138  * - **Serialization efficiency**: Encoded values serialize trivially (just
139  * size_t arrays) without type-specific serialization logic
140  * - **Network efficiency**: Fixed-size values enable efficient packing and
141  * reduce communication overhead in MPI/distributed settings
142  * - **Cross-platform compatibility**: size_t encoding provides consistent
143  * representation across different architectures
144  *
145  * @subsection codec_locality Cache Locality
146  *
147  * - **Dense storage**: Encoded columns store only size_t values, creating
148  * dense, cache-friendly memory layouts
149  * - **Better prefetching**: Uniform sizes enable more effective hardware
150  * prefetching and cache line utilization
151  * - **Reduced indirection**: For types like strings, encoding eliminates
152  * pointer chasing in index structures
153  *
154  * @subsection codec_tradeoffs Trade-offs
155  *
156  * Encoding adds a conversion step, but the benefits outweigh the cost:
157  * - Conversion is typically O(1) for primitive types
158  * - DictionaryCodec amortizes encoding cost across multiple uses
159  * - Index operations (joins, lookups) benefit significantly from uniform
160  * encoding
161  * - The encoding layer is transparent to most users via Relation API
162  *
163  * @see HashTrieIndex for how encoded values are used in index structures
164  * @see DictionaryCodec for bidirectional encoding of complex types
165  */

188 /**
189  * @brief Encode a floating-point value to size_t.
190  * @tparam T Floating-point type (float, double, etc.)
191  * @param val Value to encode
192  * @return Encoded value as size_t (bit representation)
193  * @details Uses std::bit_cast to preserve the bit pattern of the floating-point
194  * value. This is a lossless encoding that preserves exact bit
195  * patterns.
196  * @note **C++20 features**: Uses `requires` clause for type constraints,
197  * `if constexpr` for compile-time conditionals, and `std::bit_cast` for
198  * type-punning without undefined behavior.
199  * @pre sizeof(T) <= sizeof(std::size_t)
200  * @note The encoded value represents the bit pattern, not the numeric value.
201  * Use decode_from_size_t to recover the original floating-point value.
202  */
203 template <typename T>
204  requires std::is_floating_point_v<T> && (sizeof(T) <= sizeof(std::size_t))
205 constexpr std::size_t encode_to_size_t(const T& val) noexcept {
206  if constexpr (sizeof(T) == sizeof(std::size_t)) {
207  return std::bit_cast<std::size_t>(val);
208  } else {
209  using UInt = std::conditional_t<sizeof(T) == 4, uint32_t, uint16_t>;
210  return static_cast<std::size_t>(std::bit_cast<UInt>(val));
211  }
212 }

220  * the original value cannot be recovered from the hash.
221  * @note **C++20 feature**: Uses nested `requires` clauses to check that the
222  * type is not integral or floating-point, and that it supports

303 /**
304  * @brief Bidirectional dictionary codec for mapping values to/from size_t.
305  *
306  * @details DictionaryCodec provides a two-way mapping between values of type T
307  * and size_t identifiers. Unlike hash-based encoding, this provides:
308  * - **Bidirectional mapping**: Values can be encoded and decoded losslessly
309  * - **Collision-free**: Each unique value gets a unique ID
310  * - **Incremental**: New values are assigned IDs on-demand
311  * - **Memory efficient**: Uses PMR allocators for flexible memory management
312  *
313  * @tparam T The type of values to encode/decode (must be hashable and
314  * equality-comparable)
315  *
316  * @section dictionarycodec_usage Usage
317  *
318  * @code{.cpp}
319  * DictionaryCodec<std::string> codec;
320  *
321  * // Encode values (assigns IDs automatically)
322  * std::size_t id1 = codec.encode("hello"); // Returns 0
323  * std::size_t id2 = codec.encode("world"); // Returns 1
324  * std::size_t id3 = codec.encode("hello"); // Returns 0 (reuses existing)
325  *
326  * // Decode IDs back to values
327  * const std::string& val1 = codec.decode(0); // Returns "hello"
328  * const std::string& val2 = codec.decode(1); // Returns "world"
329  *
330  * // Check if ID exists
331  * if (codec.contains(0)) {
332  * // ...
333  * }
334  * @endcode
335  *
336  * @section dictionarycodec_internals Internals
337  *
338  * The codec maintains two hash maps:
339  * - `forward_`: Maps T -> size_t (value to ID)
340  * - `inverse_`: Maps size_t -> T (ID to value)
341  *
342  * IDs are assigned sequentially starting from 0. The same value always maps to
343  * the same ID (idempotent encoding).
344  *
345  * @section dictionarycodec_memory Memory Management
346  *
347  * Uses PMR (Polymorphic Memory Resource) allocators, allowing custom memory
348  * strategies (arena allocation, pooling, etc.). Defaults to the default PMR
349  * resource.
350  *
351  * @note DictionaryCodec is typically used via get_global_codec() for shared
352  * dictionaries, but can be instantiated directly for isolated codecs.
353  *
354  * @see get_global_codec for accessing shared codec instances
355  * @see Codec concept for types supporting bidirectional encoding/decoding
356  */
357 template <typename T>
358 class DictionaryCodec {
359  public:
360  /// @brief Forward map: value -> encoded ID
361  using DictMap = boost::unordered::pmr::unordered_map<T, std::size_t>;
362  /// @brief Inverse map: encoded ID -> value
363  using InverseMap = boost::unordered::pmr::unordered_map<std::size_t, T>;
364 
365  /// @brief Construct an empty DictionaryCodec.
366  /// @details Creates a new codec with no mappings. IDs will start at 0.
367  explicit DictionaryCodec() : next_id_(0) {}
368 
369  /// @brief Encode a value to a size_t ID.
370  /// @param value The value to encode
371  /// @return The encoded ID (size_t)
372  /// @details If the value has been seen before, returns its existing ID.
373  /// Otherwise, assigns a new sequential ID and stores the mapping.
374  /// @note **C++17 feature**: Uses `if` statement with initialization
375  /// (`if (auto it = ...)`) for efficient lookup and initialization in
376  /// a single statement.
377  /// @note Encoding is idempotent: encoding the same value multiple times
378  /// returns the same ID.
379  std::size_t encode(const T& value) {
380  if (auto it = forward_.find(value); it != forward_.end()) {
381  return it->second;
382  }
383  std::size_t id = next_id_++;
384  forward_.emplace(value, id);
385  inverse_.emplace(id, value);
386  return id;
387  }
388 
389  /// @brief Decode an ID back to its original value.
390  /// @param id The encoded ID to decode
391  /// @return Const reference to the original value
392  /// @throw std::runtime_error if the ID doesn't exist in the dictionary
393  /// @details Returns a reference to the stored value. The reference remains
394  /// valid as long as the codec exists and the value isn't cleared.
395  const T& decode(std::size_t id) const {
396  auto it = inverse_.find(id);
397  // if (it == inverse_.end()) {
398  // throw std::runtime_error("Invalid encoded value for dictionary");
399  // }
400  return it->second;
401  }
402 
403  /// @brief Check if an ID exists in the dictionary.
404  /// @param id The ID to check
405  /// @return true if the ID exists, false otherwise
406  /// @details Useful for checking validity before calling decode().
407  /// @note **C++20 feature**: Uses `std::unordered_map::contains()` method
408  /// (C++20) instead of `find() != end()` pattern for clearer code.
409  bool contains(std::size_t id) const {
410  return inverse_.contains(id);
411  }
412 
413  /// @brief Get the number of unique values in the dictionary.
414  /// @return Number of distinct values that have been encoded
415  /// @details This equals the number of unique IDs assigned (next_id_ if no
416  /// values have been cleared).
417  std::size_t size() const {
418  return forward_.size();
419  }
420 
421  /// @brief Clear all mappings and reset the codec.
422  /// @details Removes all value-to-ID mappings and resets the ID counter to 0.
423  /// After clearing, encoding will start assigning IDs from 0 again.
424  void clear() {
425  forward_.clear();
426  inverse_.clear();
427  next_id_ = 0;
428  }
429 
430  private:
431  DictMap forward_; ///< Forward mapping: value -> ID
432  InverseMap inverse_; ///< Inverse mapping: ID -> value
433  std::size_t next_id_; ///< Next ID to assign (incremented on new encodings)
434 };

612 /// @brief Concept requiring all elements of a tuple to satisfy ColumnElement.
613 /// @details This concept checks that every type in the tuple satisfies the
614 /// ColumnElement concept, enabling tuple-based Relation templates
615 /// while maintaining type safety.
616 /// @note **C++20 feature**: Uses C++20 concepts with fold expressions
617 /// (`&& ...`) to check all tuple elements at compile time. The fold
618 /// expression iterates over all elements in the tuple using
