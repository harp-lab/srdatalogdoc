Detailed Description

template<Semiring SR, ColumnElementTuple AttrTuple, typename ValueType = std::size_t, typename RowIdType = uint32_t>
class SRDatalog::HashTrieIndex< SR, AttrTuple, ValueType, RowIdType >::NodeHandle

Cursor for navigating and querying nodes in a HashTrieIndex.

NodeHandle provides a lightweight, cursor-based API for traversing the trie structure. It acts as a non-owning view into a specific node and provides methods to query the node's state and navigate to children.

Lifecycle

  • Default-constructed handles are invalid (valid() returns false)
  • Handles are created by HashTrieIndex methods (root(), prefix_lookup())
  • Handles remain valid only as long as the parent HashTrieIndex exists (non-owning view - caller must ensure HashTrieIndex lifetime)
  • Handles are trivially copyable (POD-style: just a raw pointer and node ID)

Node Types

Nodes can be either:

  • Internal nodes (is_leaf() == false): Contain mappings to child nodes. Use values() to enumerate possible next-level keys.
  • Leaf nodes (is_leaf() == true): Contain posting lists of row IDs. Use rows() to get matching row IDs.

Usage

auto node = idx.root(); // Start at root
if (node.valid() && !node.is_leaf()) {
// Enumerate all possible values at first level
for (auto key : node.values()) {
auto child = node.prefix(key);
if (child.valid() && child.is_leaf()) {
// Process rows matching this key
for (auto row_id : child.rows()) {
// ...
}
}
}
}
