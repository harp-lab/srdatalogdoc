19  * @brief Sorted Array Index (Read-Only B-Tree / Flat Index).
20  *
21  * @details This index stores the indexed columns in a contiguous, sorted layout.
22  * Unlike HashTrieIndex, it does not use a pointer-based tree structure.
23  * Instead, "nodes" are represented by ranges [start, end) over the sorted arrays.
24  *
25  * @section tradeoffs Trade-offs vs HashTrieIndex
26  * - **Pros:**
27  * - Extreme memory locality (linear scan friendly).
28  * - Lower memory overhead (no node objects, hash maps, or pointers).
29  * - Supports Range Queries (e.g., x > 5) natively via binary search.
30  * - **Cons:**
31  * - Point lookups are O(log N) instead of O(1).
32  * - `values()` (enumerating children) returns a range containing DUPLICATES.
33  * Algorithms must handle this (e.g., using skip-scanning or upper_bound).
34  *
35  * @tparam SR The semiring type
36  * @tparam AttrTuple The attribute tuple type
37  * @tparam ValueType The type for encoded values (default: uint32_t for memory efficiency)
38  * @tparam RowIdType The type for row IDs (default: uint32_t, must be able to represent all row
39  * indices)
40  */
